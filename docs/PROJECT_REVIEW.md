# Lexica 项目审查与优化记录

日期：2026-09-13。范围：当前本地 SvelteKit + Tauri + Rust + SQLite 项目。

## 审查结论

项目的优势是离线词典、词形回退、记忆事件流和分层实现已经存在。主要短板是产品层：缺少统一导航和视觉层级，查词、积累与复习之间没有完整路径，用户偏好和操作反馈不足。本轮在原架构上完善这条路径。

## 已落实

| 原问题 | 本轮改动 | 主要位置 |

## 验证方法与边界

- `npm run check`：前端类型与 Svelte 检查。
- `npm run build`：正式前端构建，浏览器示例词库不会进入生产包。
- `npm run test:e2e`：10 项界面测试，包含 480px 和 1180px 全页面溢出检查，以及浅色/深色截图。
- `cargo test`：63 项 Rust 测试，覆盖新旧版本迁移保留记录、笔记/收藏存储、笔记长度、查询分页、本地日期统计、复习生成与判分等。
- `cargo clippy --all-targets -- -D warnings`：Rust 静态检查。
- Windows 程序通过 `cargo build --release --features custom-protocol --bin lexica` 生成，嵌入本轮前端资源。

浏览器交互测试使用独立的 IPC 契约夹具；SQLite 与记忆规则在 Rust 中测试。它们不等价于完整的 Windows WebView2 人工验收。浏览器只读预览明确显示提示，不会写入桌面应用数据。`review-fixture.png` 使用测试用例数据，其他页面预览使用内置种子词库。

发音只使用系统已安装的离线英语语音；没有可用语音时按钮禁用。没有捏造音频或联网回退。新版判分规则只作用于之后的复习，旧记录不会被重新判分。

没有为了测试重新导入完整的 ECDICT，也没有对用户的实际学习记录做批量修改。大词库性能优化基于查询路径审查，本轮不声称已经完成百万词库的延迟基准测试。

## 接下来的优先级

### P1：数据质量与可迁移性

1. **补足词典内容质量**：重点提升常用词的例句、词性分义、英英解释、词形信息完整度。界面无法弥补词库中的缺项。应先统计缺失率，再选择要补全的数据来源。
2. **个人数据导出、备份与恢复**：针对收藏、笔记和学习事件做版本化导出、导入预览和冲突合并。当前是本机存储，没有跨设备同步或用户界面中的备份入口。
3. **原生文件选择与导入进度**：把填写数据库路径升级为本地文件选择器，提供分批进度、取消和失败恢复。当前只显示运行状态和最终新增数量。
4. **Windows 实机交互验收**：高 DPI、系统离线语音、WebView2 剪贴板、输入法、长词条、真实大词库导入期间的响应。

### P2：查阅能力

1. 中文反查、按释义全文检索，并明确区分词头与释义搜索。
2. 阅读选词浮窗、应用内全局搜索快捷键、系统托盘；先确认目标平台与常见阅读场景。
3. 用户句子收藏、来源链接和标签，让个人词汇拥有更完整的上下文。
4. 离线英美发音音频与播放偏好，优先可用性和来源质量。

### P3：长期演进

1. 用实际学习数据评估间隔算法，再调整记忆模型。避免仅凭界面“已掌握”标签推断真实掌握程度。
2. 复习会话断点续做、按场景复习和困难词回顾。
3. 需要多设备时再增加可选同步，并先定义离线冲突策略。
